# Roadmap and issue map

Work is tracked in GitHub Issues. Each issue needs a visible outcome and acceptance criteria.

## M0 — Foundation
Research, product scope, UX, safety, architecture, repository conventions.

## M1 — Landing page
Responsive page, visual system, content, accessibility, SEO/social metadata, QA.

## M2 — Flutter foundation
Project scaffold, theme, routing, DI, localisation, reusable components, tests.

## M3 — Core journeys
Home, Learn library/article, optional check-in, breathing/grounding, Support guidance, settings.

## M4 — Validation and quality
Accessibility, performance, offline, clinical/safety review, Hausa translation review, user-testing plan.

## M5 — Backend discovery (not implementation)
Define API boundaries, privacy/security architecture, provider verification operations, AI safety case and governance after frontend review.

Complete and review the landing page first, then immediately continue with Flutter. Do not block frontend delivery on backend decisions.

## Definition of done
Acceptance criteria met; loading/empty/error states handled; accessibility and responsive behaviour checked; no fake live data or unverified health claims; tests/format/static analysis pass; docs updated.
